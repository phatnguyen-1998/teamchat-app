# 確認事項リスト

`docs/spec.md` と `mockup/` を突き合わせて見つかった、「書かれていないこと」と「食い違い」のリストです。仕様書 §6 に従い、**自分では決めず、想定を添えて**質問します。

- 質問は「〜という想定ですが、〜ですか」の形で書いています。想定のとおりなら「はい」だけで答えられます
- **優先度**: 高 = 答えしだいで、権限・データ・API の作りが変わる、または情報が漏れうる。中 = 画面や処理の細部が変わる。低 = 変わっても影響が小さい
- **関連**: [features.md](features.md) の機能ID
- **回答／決定** の欄に、クライアントの回答を言葉を直して記録しています。先頭の印の意味は次のとおりです
  - 【確定】想定のとおり、または回答が明確で問題がないもの（23件）
  - 【要再確認】回答に問題や不明な点があり、クライアントにもう一度確かめるもの（Q-01、Q-05）
  - 【仮置き】クライアントから「そちらで決めて」と任された部分を、こちらで仮に決めたもの（Q-23）

## アカウント

### Q-01 登録できる人の範囲

- **質問**: 登録画面は、メールアドレスのドメインなどの制限をかけず、誰でも登録できる（社内ネットワークからしか開けない運用で守る）という想定ですが、社員以外が登録できないようにする仕組み（社内ドメインのみ許可、招待制など）は必要ですか
- **根拠**: 仕様書 §3-1「社員が自分でアカウントを作れる」、§2 / `register.html`（制限の記載なし）
- **関連**: F-01 ／ **優先度**: 高
- **回答／決定**: 【要再確認】メールアドレスのドメイン制限や招待制は設けず、誰でも登録できる。
  - 問題点: 質問では「社内ネットワークからしか開けない運用で守る」ことを前提にしていましたが、その前提への回答がありません。インターネットに公開すると、社員以外も登録して公開チャンネルを読み書きできてしまいます（仕様書 §1 は「使うのは社員だけ」）
  - 確認すること: 社内ネットワークの中だけで動かす前提でよいか

### Q-02 アカウントの入力ルール

- **質問**: メールアドレスは重複して登録できない（大文字小文字は区別しない）、表示名は重複してよい、パスワードは8文字以上で文字の種類の制限はない、という想定ですが、よろしいですか。表示名が重複すると、メンバー追加（Q-09）で見分けにくくなります
- **根拠**: 仕様書 §3-1, §5-1 / `register.html`, `members.html`（表示名で探す）
- **関連**: F-01, F-02 ／ **優先度**: 高
- **回答／決定**: 【確定】想定のとおり（はい）

### Q-03 ログイン前後の遷移

- **質問**: 登録を終えたらそのままログイン状態になり、登録後・ログイン後の最初の画面はチャンネル一覧、ログアウト後はログイン画面、という想定ですが、よろしいですか。未ログインで他の画面を開いたらログイン画面へ移し、ログイン後に元の画面へ戻します。ログイン状態は標準的な期間だけ保ち、「ログイン状態を保持する」の選択肢は設けません。モックにはログイン後のトップ画面がありません
- **根拠**: 仕様書 §3-1（遷移の記載なし）/ `login.html`, `register.html`
- **関連**: F-02, F-03, F-04 ／ **優先度**: 中
- **回答／決定**: 【確定】想定のとおり（はい）

## チャンネル

### Q-04 自分に見えないプライベートチャンネルの扱い

- **質問**: 自分がメンバーでないプライベートチャンネルは、サイドバー・チャンネル一覧・検索結果に名前も含めて出ず、URLを直接開いても「見つかりません」と表示して、存在そのものを知らせない（存在しないチャンネルと同じ見え方にする）という想定ですが、よろしいですか
- **根拠**: 仕様書 §3-2, §3-6, §3-7 / `channels.html`（作成者にだけ「メンバー」「編集」が出る注記）
- **関連**: F-05, F-06, F-10, F-21, F-23 ／ **優先度**: 高
- **回答／決定**: 【確定】想定のとおり（はい）

### Q-05 チャンネル名の重複と使える文字

- **質問**: 同じ名前のチャンネルを複数作れる（重複のチェックをしない）という想定ですが、よろしいですか。重複をエラーにすると、自分に見えないプライベートチャンネルの名前が存在することが分かってしまうため、この想定にしています。名前に使える文字は制限なし（前後の空白は取り除く）という想定です。重複を禁止したい場合は、プライベートチャンネルの扱いも教えてください
- **根拠**: 仕様書 §3-2, §3-7「プライベートチャンネルの情報は、チャンネル名も含めて、いっさい含めない」/ `channel-new.html`
- **関連**: F-07 ／ **優先度**: 中
- **回答／決定**: 【要再確認】想定を変更し、チャンネル名の重複を禁止する。
  - 名前の長さは50文字以内。文字の種類の制限とは読み取れないため、長さの制限だけとして扱う
  - 重複を調べる範囲は、「公開チャンネル同士」と「プライベートチャンネル同士」で別々にする。公開とプライベートで同じ名前があってもよい
  - 問題点: プライベート同士で重複を禁止すると、自分に見えないプライベートチャンネルの名前が分かってしまいます。たとえば「採用プロジェクト」を作ろうとして「すでに使われています」と出れば、その名前のプライベートチャンネルがどこかにあると分かります。Q-04 の「存在そのものを知らせない」と食い違います
  - 提案: プライベートは「自分がメンバーのプライベートチャンネルの中だけ」で重複を調べる。見えない名前とは衝突しないので、漏れません
  - 確認すること: 上の提案でよいか。あわせて、「A」と「a」のような大文字小文字の違いを同じ名前とみなすか
