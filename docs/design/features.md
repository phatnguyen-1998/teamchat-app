# 機能一覧と、今回作らないもの

チームチャットアプリの機能一覧です。確認事項は [questions.md](questions.md) にあり、各機能の「確認」列から番号で辿れます。

**根拠にした資料**: `docs/spec.md`（以下「仕様書」。§は章番号）、`mockup/` の全HTML（10枚）、`mockup/design-guide.md`

**読み方**

- 「できる人」: 未ログイン ／ 社員（ログイン済み）／ 作成者（そのチャンネルを作った人）／ 本人（そのメッセージを書いた人）
- 「根拠」: 仕様書の章と、見本にした画面。**「モックのみ」は仕様書に文章がなく、モックにだけ現れるもの**
- 確認事項の答えしだいで、内容が変わる機能があります

## 2. 今回作らないもの

### 2-1. 仕様書・モックに「作らない」と書いてあるもの

| 作らないもの | 理由（仕様書の記述） | 根拠 |
|:--|:--|:--|
| 新着メッセージの自動表示（画面を開いたままで届く） | 画面を開き直して確認できれば十分 | §4 |
| 通知（メール・スマートフォンへの通知） | まずは社内で使い始められる形を優先 | §4 |
| 1対1のダイレクトメッセージ | チャンネルでの会話に絞る | §4 |
| ファイル・画像の添付 | 文章のやり取りに絞る | §4 |
| メッセージへのリアクション（絵文字） | 会話ができることを優先 | §4 |
| 未読・既読の管理 | 同上 | §4 |
| 管理者による全体管理（利用者の停止、他人のチャンネルの管理） | 運用が固まってから考える | §4 |
| 書き込み・変更ができるAPI | 今回は読み取り専用で足りる | §3-7 |
| スマートフォン向けの表示（レスポンシブ） | PCのブラウザだけ考える | §5-2 / `design-guide.md` §3 |
| 公開／プライベートの切り替え（作成後） | モックの編集画面に「あとから変更できません」とある | `channel-edit.html` |

§4 の7つは、モックにもその画面や操作がないことを確認済みです（リアクションの絵文字、添付ボタン、DM、未読の印、管理者画面はどの画面にもありません）。

### 2-2. どこにも書いてないので、作らない想定のもの（要確認）

仕様書にもモックにもない機能です。「作らない」と私が決めたのではなく、**作らない想定で [Q-24](questions.md) に挙げています**。回答しだいで、機能一覧に加えます。

- パスワードの再設定・変更
- 表示名やメールアドレスの変更、退会（アカウント削除）
- メンバー自身がチャンネルから抜ける操作
- チャンネルの作成者の変更（譲る）、作成者が複数いる状態
- メッセージの Markdown 表示、URLの自動リンク、メンション（@）
- 1つのチャンネルの中だけの検索
- チャンネルの保管（アーカイブ）、並べ替え、お気に入り

## 3. 機能以外で守る条件

機能ではないので番号は付けません。

- アプリの名前は「**チームチャットアプリ**」で統一する（§5-3）
- 見た目は `mockup/` に合わせる。合わせるのは、並び・項目・言葉づかい・状態の見せ方（§5-3）
- 色・字・余白・状態（エラー・空・編集中など）は `mockup/design-guide.md` に従う
- 画面の最小幅は 1280px（`design-guide.md` §3）
- 使うのはPCのブラウザ（§5-2）
